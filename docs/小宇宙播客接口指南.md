# 小宇宙播客接口分析指南

> 对小宇宙（Xiaoyuzhou FM）接口的公开资料整理 + 多份开源实现交叉核对。前 5 节来自公开仓库的源码与文档，**未对小宇宙发起过真实请求**；第 6.1 节是在本机 QQ 音乐客户端上的实测。
>
> 整理日期：2026-10-26。接口为非公开接口，随时可能改名、改字段或加风控。文中不记录任何 access token、refresh token、手机号。

## 0. 2026-10-27 实测更新（本仓库「小宇宙 beta」已接入）

| 项 | 结论 |
|---|---|
| 短信登录 | **不可用**：`api` 的 `/v1/auth/sendCode` 返回 `1003 empty captchaVerifyParam`，`podcaster-api` 的 `/v1/auth/send-code` 要求 `body.captcha`，都需要人机验证 |
| 扫码登录 | **可用**：`POST https://web-api.xiaoyuzhoufm.com/v1/auth/qrcode/create {"clientId":"xyz-web"}`（头 `x-midway-app-id: v6worU4NnWyL`）→ `{id, url}`，把 `url` 画成二维码；每 1.5s `POST /v1/auth/qrcode/login {"id"}` → `WAITTING` / `SCANNED` / `CONFIRMED` / `USED`；`401 code 21` 为过期 |
| 登录成功判定 | 官方页面把 `CONFIRMED` 和 **`USED`** 都当成功；token 以 `x-jike-access-token` / `x-jike-refresh-token` Cookie（请求带 `x-jike-allow-app-token-in-cookie: true`）或响应头下发 |
| 网页 token 能否调 App 接口 | **能**：用扫码拿到的 token 调 `api.xiaoyuzhoufm.com`（iOS 2.57.1 请求头），`profile/get`、`top-list/get`、`inbox/list`、`subscription/list`、`search/create`、`podcast/get`、`episode/list`（含翻页）全部成功 |
| 音频 | `media.xyzcdn.net` 的 m4a 直链无需鉴权，本仓库播放器经 Media Foundation 可解（1h16m 的单集整文件下完约 5s） |
| 图片尺寸 | `@thumbnail` 150px、`@small` 300px、`@middle` 800px |
| 手机号登录 | 两个 `send-code` 都要阿里云验证码 2.0（`AliyunCaptcha.js`，`prefix: kn7vz1`，滑块）。可行做法：在 WebView 打开 `https://accounts.xiaoyuzhoufm.com/login?redirectURL=…`，登录后从 `xiaoyuzhoufm.com` 的 Cookie 读 `x-jike-access-token` / `x-jike-refresh-token`。[QWE38qwe/xiaoyuzhou-desktop](https://github.com/QWE38qwe/xiaoyuzhou-desktop) 仍直接 POST `send-code`（不带 captcha），现已失败 |
| 编辑精选 | `POST /v1/editor-pick/list {}` → `data[] {date, picks[] {episode, comment{text, author}}}`，`loadMoreKey` 是日期字符串，原样回传翻页 |
| 首页信息流 | `POST /v1/discovery-feed/list {"returnAll":"false", "loadMoreKey"}` 分 4 页，`loadMoreKey` 依次为（无）→ `topList` → `discoveryTopic` → `pick`。模块：`DISCOVERY_EPISODE_RECOMMEND`（为你推荐，`data.target[] {recommendation, episode}`）、`EDITOR_PICK`（当天编辑精选）、`TOP_LIST`（三个榜）、`CATEGORY_ENTRANCE`（分类入口）、`DISCOVERY_COLLECTION`（`data[]`，如「为你精选的节目」`target[] {recommendation, podcast}`、主题合集 `target[] {episode}`）、`NEW_POWER`（宝藏新节目，`data.items[]` 为带 `recommendation` 的节目，`serialNumber` 为期数）、`DISCOVERY_PICK`（TA们的喜欢，`data[].pick {story.text, episode, user}`）、`PILOT`（TA们开始创作新播客）；`DISCOVERY_HEADER`/`DISCOVERY_BANNER`/`ONBOARDING_PROMPT` 是 App 内跳转与横幅。已接入为「推荐」页签 |
| 分类 | `POST /v1/category/list-all {}` → 19 个分类 `{id, name}`；`POST /v1/category/podcast/list-tabs {categoryId}` → `全部/近期热门/为你推荐`（`ALL/HOT/RECOMMEND`）；`POST /v1/category/podcast/list-by-tab {categoryId, tab, omitSubscribed:false, loadMoreKey}` → `data[] {podcast, episode}`，每页 10 个，`loadMoreKey` 为数字。已接入为分类页 |
| 官方文字稿 | `POST /v1/episode-transcript/get {eid, mediaId}` 返回 `transcriptUrl`，文件为 `[{text, startMs}]`；但对本客户端返回的内容与节目无关（疑似占位/反爬），**不可用** |
| 实时播放 | 浏览器扩展靠 `<audio src>` 边下边播；本仓库用 Go 实现的 `IStream` 把下载缓冲交给 Media Foundation，m4a 的 `moov` 在文件头，0.15s 开播 |

## 0.1 结论速览（2026-10-26 资料整理）

| 问题 | 结论 |
|---|---|
| API 主域名 | `https://api.xiaoyuzhoufm.com`；主播后台另用 `https://podcaster-api.xiaoyuzhoufm.com` |
| 鉴权方式 | 请求头 `x-jike-access-token`；登录成功后 token 在**响应头**下发，不在 body |
| 设备标识 | 请求头 `x-jike-device-id`（社区普遍复用固定值） |
| 未登录调 API | 一律 401，没有匿名 JSON 接口 |
| 唯一免登录通道 | 网页 `https://www.xiaoyuzhoufm.com/podcast/{pid}`、`/episode/{eid}`，数据在页面内嵌的 `__NEXT_DATA__` |
| 音频地址 | 单集详情里的 `media.source.url` 或 `enclosure.url`，CDN 为 `media.xyzcdn.net` |
| 付费 / 私有单集 | 走 `GET /v1/private-media/get`，要求登录且账号已购买 |
| 网页直连 | 必须带真实浏览器 UA，否则 403 |
| 稳定性 | 低：客户端版本号（2.57.1 / build 1576）和设备 ID 都是硬编码，服务端一升级就集体失效 |
| QQ 音乐内置模块 | 信息流卡片 `type=900, subtype=994`，`id` 就是 QQ 音乐的曲目 id |
| 内置模块能否取数据 | **能**：节目 = 专辑（type `人声音频`）、单集 = 歌曲、主播 = 歌手，现有接口全部打通 |

## 1. 三条通道

| 通道 | 域名 | 鉴权 | 能拿到什么 | 风险 |
|---|---|---|---|---|
| App 私有 API | `api.xiaoyuzhoufm.com` | `x-jike-access-token` | 全量：首页流、榜单、搜索、订阅、评论、播放进度、付费音频 | 逆向接口，有账号被风控/封禁的社区报告 |
| 主播后台 API | `podcaster-api.xiaoyuzhoufm.com` | 登录态 | 仅用于登录、稿件与逐字稿管理 | 需主播账号 |
| 网页 SSR | `www.xiaoyuzhoufm.com` | 无 | 播客资料 + **最近约 15 集**、单集详情 + 音频直链 | 改版即失效；无搜索、无分页、无付费音频 |

> 注意：`ultrazg/xyz` 文档里的 `/podcast_detail`、`/episode_detail` 是它本地代理服务的路由，**不是**上游真实路径。真实上游路径见第 3 节。

## 2. 鉴权

### 2.1 登录流程（短信验证码）

```text
POST {api}/v1/auth/sendCode                  {"mobilePhoneNumber":"...","areaCode":"+86"}
POST {api}/v1/auth/loginOrSignUpWithSMS      {"areaCode":"+86","verifyCode":"1234","mobilePhoneNumber":"..."}
POST {api}/app_auth_tokens.refresh           Header: x-jike-refresh-token: <refresh>
```

- **登录响应的 token 在头里**：`x-jike-access-token`、`x-jike-refresh-token`；用户信息在 body（`data.user.uid` / `data.user.nickname`）。
- 刷新接口无 body，响应体返回新的 `x-jike-access-token` / `x-jike-refresh-token`，并带 `success: true`。
- 另有一个后台登录入口：`POST https://podcaster-api.xiaoyuzhoufm.com/v1/auth/login-with-sms`，token 同样在响应头。

### 2.2 业务请求头

静态伪装（模拟 iOS 客户端，社区通行的基线）：

```http
User-Agent: Xiaoyuzhou/2.57.1 (build:1576; iOS 17.4.1)
App-Version: 2.57.1
App-BuildNo: 1576
BundleID: app.podcast.cosmos
OS: ios
OS-Version: 17.4.1
Model: iPhone14,2
Manufacturer: Apple
Market: AppStore
app-permissions: 4
WifiConnected: true
Accept-Language: zh-Hans-CN;q=1.0
abtest-info: {"old_user_discovery_feed":"enable"}
x-custom-xiaoyuzhou-app-dev: ""
```

每次请求动态生成：

```http
x-jike-access-token: <access token>
x-jike-device-id: <device id>
Local-Time: <RFC3339，带时区偏移>
Timezone: Asia/Shanghai
```

差异点（实测于源码）：`/v1/private-media/get` 的 `app-permissions` 是 `100000`；`/v1/episode/list-by-filter` 与 `/v1/live-stats/report` 的 `abtest-info` 为 `{}`；`/v1/episode-played/list` 额外带 `X-Online-Host: api.xiaoyuzhoufm.com`。

## 4. 请求与返回

### 4.1 信封

```json
{ "data": { }, "success": true, "msg": "OK" }
```

- 列表类：`data` 通常是**数组**，同级带 `loadMoreKey`。
- 详情类：`data` 是对象；部分第三方文档示例还多包一层（`data.data`），说明不同版本/不同封装存在差异。
- 实现建议：先把 `data` 收成 `json.RawMessage`，确认结构后再二次解析；不要假定固定层级。
- ID 为 24 位十六进制字符串（如 `61791d921989541784257779`）。

### 4.2 单集字段（`/v1/episode/get`）

```text
eid, pid, type("EPISODE"), title, description, shownotes
duration(秒), pubDate(ISO8601), status("NORMAL"), payType("FREE"/付费)
playCount, commentCount, clapCount, favoriteCount

```

### 4.3 播客字段（`/v1/podcast/get`）

### 4.4 音频地址

优先级：

1. `media.source.url`（主用）
2. `enclosure.url`（兜底）

公开单集是 CDN 直链（`https://media.xyzcdn.net/...`），**不再需要额外鉴权头**，但可能校验 Referer/UA；付费或私有单集必须走：

```text
GET /v1/private-media/get?dubbing=false&eid={eid}
Header: x-jike-access-token
```

未购买时通常返回 4xx，或返回极小文件（社区反馈约 0.01 MB）。

## 5. 免登录网页通道

### 5.1 为什么可行

小宇宙网页是 Next.js SSG，服务端渲染时把数据塞进 HTML 的 `<script id="__NEXT_DATA__" type="application/json">`。抓 HTML 解析这段 JSON 即可，不需要 token。

### 5.2 抓取步骤

```text
GET https://www.xiaoyuzhoufm.com/podcast/{pid}   -> props.pageProps.podcast（含 episodes[]，约最近 15 集）
GET https://www.xiaoyuzhoufm.com/episode/{eid}   -> props.pageProps.episode（含 media / enclosure）
```

必要条件：**真实浏览器 UA**，否则 403。

```go
// 取 __NEXT_DATA__ 的最小实现
var nextRe = regexp.MustCompile(`(?s)<script id="__NEXT_DATA__" type="application/json">(.*?)</script>`)

func nextData(html []byte) (map[string]any, error) {
    m := nextRe.FindSubmatch(html)
    if m == nil {
        return nil, errors.New("__NEXT_DATA__ not found")
    }
    var v map[string]any
    return v, json.Unmarshal(m[1], &v)
}
// 播客：v["props"]["pageProps"]["podcast"]
// 单集：v["props"]["pageProps"]["episode"]
```

### 5.3 限制

- 节目页只有约 15 集，**没有分页**；要全量必须走登录态 API。
- 没有搜索入口：网站 `/search?q=` 是 404。
- 逐字稿是 App 专属，接口在主播后台 `/management/episode-transcript/*`，公开网页没有。
- 改版就会变；字段缺失时要能降级，不要 panic。
- 托管在 `feed.xyzfm.space/{token}.xml` 的节目另有 RSS，可作第三条路；请求需声明 gzip，否则 1.5 MB 明文容易超时截断。

## 6. 与本仓库的对接评估

有两条完全不同的路，成本差很多。

### 6.1 路径 A：QQ 音乐内置的「小宇宙」（推荐，已实测）

小宇宙在 QQ 音乐里的内容不是外部 H5，而是**已经进了 QQ 音乐曲库**：

| 小宇宙概念 | QQ 音乐里的形态 | 关键字段 |
|---|---|---|
| 节目 / 播客 | 专辑 | `albummid`，专辑 `type` 为 `人声音频` |
| 单集 | 歌曲（track） | `songid` / `songmid`，`interval` 就是单集秒数 |
| 主播 | 歌手 | `singermid`，`SingerAlbums` 能列出他名下的所有节目 |

实测链路（2026-10-26，每步只发一次请求，未遍历任何列表）：

1. 手机端信息流 `RecommendFeed` 的入口卡片：
   `type=900, subtype=994, jumptype=10046, title="小宇宙", id=736382210`，
   `scheme=qqmusic://qq.com/ui/openRN?p={"key":"TodayFmAudio",...}`。
2. `music.trackInfo.UniformRuleCtrl / CgiGetTrackInfo` 用这个 id 取到单集：
   `E255 ...`，`mid=003cq5oI3dfvx1`，`album=知行小酒馆`，`interval=4167`（69 分钟）。
3. `SongURL` 直接拿到 128k MP3：
   `https://isure.stream.qqmusic.qq.com/M500003cq5oI3dfvx1.mp3?...`，
   `Size128=66,685,223`，没有 320 / FLAC / AAC。
4. `AlbumDetail(000omnsg344lUQ)` 返回 **253 集**，就是这个播客的全部单集。
5. `SingerAlbums(主播 mid)` 返回主播名下的 2 个节目（`知行小酒馆`、`投资ABC`）。
6. 搜索 `知行小酒馆` 的直达卡片：`label="播客"`、`desc="有知有行 · 253集"`，`mid` 就是 albummid。

也就是说，**现有 `internal/qqmusic` 已经能打通「搜索 → 节目 → 单集 → 播放」全链路**，不需要小宇宙的 token，也不用改协议。

| 点 | 结论 |
|---|---|
| 入口 | `RecommendFeed` 的 900/994 卡片；`id` 当普通歌曲 id 用 |
| 发现 | QQ 音乐搜索（直达卡片会标「播客」）→ `AlbumDetail` |
| 播放 | `SongURL`，实测只有 128k MP3，`player` 直接能播，没有 AAC 整文件等待问题 |
| 内存 | 69 分钟约 64 MB，`buffer` 全量驻留；比 `.m4a` 方案好，但仍要接受这个量级 |
| 限制 | 小宇宙推荐页自身的排序 / 编辑推荐没有找到对应接口；能拿到什么取决于信息流卡片与搜索 |
| UI | 现有专辑页可复用；需要给「播客」加文案区分（专辑 `type=人声音频`、直达卡片 `label=播客`） |

### 6.2 路径 B：小宇宙官方接口（不推荐）

| 点 | 现状 | 结论 |
|---|---|---|
| 免登录数据 | `__NEXT_DATA__` 可用 | 只适合做详情补充 |
| 音频格式 | 主流 `.m4a`（AAC） | `aac_windows.go` 要**整文件下完**才开始播 |
| 内存 | `buffer` 全量驻留 | 50–100 MB 长播客体验差 |
| 风险 | 逆向接口、有封号报告 | 不值得为同一批内容再开一条 |

结论：**优先走 6.1**。6.2 只在需要 shownotes / 逐字稿 / 小宇宙独有内容时再考虑。

### 6.3 小宇宙 id 与 QQ 音乐 id 能不能互查

**不能按 id 直接查**，两边是独立的 id 空间：

| 对象 | 小宇宙 | QQ 音乐 |
|---|---|---|
| 节目 | pid `6013f9f58e2f7ee375cf4216`（知行小酒馆） | albummid `000omnsg344lUQ` |
| 单集 | eid `6adb068cc96c8942ec110ee1`（E255） | songmid `003cq5oI3dfvx1` |
| 音频 | `media.xyzcdn.net/6013f9f5.../lmrfBKmfdmUn7-CjfvaeogEO6FQI.m4a` | `isure.stream.qqmusic.qq.com/M500003cq5oI3dfvx1.mp3` |

验证结果：

- 用 pid / eid 当关键词搜 QQ 音乐：**没有直达卡片**，返回的是「圆周率」「押韵歌」这类模糊匹配。
- `CgiGetTrackInfo` 与 `GetAlbumDetail` 的原始 JSON 里搜不到 pid / eid，也没有 xyz / podcast 字段。
- 两边音频不同源：小宇宙是 `media.xyzcdn.net` 的 m4a，QQ 音乐是自家 CDN 的 mp3，音频文件名（`lmrf...` vs `003cq5oI3dfvx1`）无对应关系。

能用的对齐方式是**节目名 + 单集标题 + 时长**。实测「知行小酒馆」最近 8 集，标题逐字相同、时长逐秒相同：

| 单集 | 小宇宙 eid | 时长 | QQ 音乐 songid | interval |
|---|---|---|---|---|
| E255 | `6adb068cc96c8942ec110ee1` | 4167 | `736382210` | 4167 |
| E254 | `6ad1c92a0e4e410a05bdc907` | 7466 | `734396142` | 7466 |
| E253 | `6ac89152195d838e2aef2e5f` | 4734 | `732454516` | 4734 |
| E252 | `6aace1189d326477816b0a46` | 3882 | `727014583` | 3882 |
| E251 | `6aa37bcd492687f6aad83995` | 6569 | `724864930` | 6569 |

所以从小宇宙 id 出发，只能这样落地：

```text
小宇宙 pid → 节目名（用它的网页/接口）→ QQ 音乐搜索节目名 → albummid
          → AlbumDetail → 按「E编号 + 标题 + duration」匹配 → songid → SongURL
```

反向（QQ 音乐 → 小宇宙）同理。匹配时优先用 `E255` 这类编号，再用标题和 ±2 秒的时长容错。

## 8. 风险与限制

1. **封号风险**：社区多个项目（`xyz-dl`、`xyz`）明确警告第三方登录与批量下载会触发风控甚至封禁。不要用主账号，不要高频。
2. **版本墙**：请求头里的 `2.57.1` / `1576` 是写死的；服务端升级后可能整体拒绝。
3. **设备指纹**：固定 `x-jike-device-id` 在服务端看是同一台设备的高频请求，是最明显的机器特征。
4. **付费内容**：`isPrivateMedia=true` 必须走私有媒体接口且账号已购；不要尝试绕过。
5. **字段漂移**：接口随时改名/改层级；解析要容错，失败走降级而不是 panic。
6. **合规**：接口为非公开接口，仅供学习研究；不要把抓到的内容再分发，也不要把它做成公开服务。
